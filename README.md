# Kvia — Tender matching for SMEs

Prototype of the flagship service "Tender Matching" for the AI Adoption and Innovation Centre
(AI for Business group assignment, BI, autumn 2026). Build specification: `SPEC.md`.

**Status: Phase 1 (mock build) complete.** Real notices (Doffin snapshot 2026-10-26) and the synthetic profiles
P1–P3 run through the full chain; the AI steps are replaced by MOCK outputs generated by code, and the tender
documents by watermarked placeholder PDFs. Every mock view carries the banner
"MOCK DATA — tender documents not yet processed". Phase 2 (real AI run) starts only on the team's command
(SPEC §17–18; open items in `docs/team_reminders.md` and `docs/conflict_log.md`).

## Repository map

| Path | What |
|---|---|
| `SPEC.md`, `CLAUDE.md`, `docs/` | Build spec, agent instructions, authoritative project documents, team reminders, **conflict log** |
| `data/raw/` | Doffin export (unaltered). Phase 2: original tender PDFs in `data/raw/tender_docs/{doffin_id}/` |
| `data/profiles/` | P1–P3 as JSON (Table A1 data model), generated from the .docx by `pipeline/tools/build_profiles.py` |
| `data/adviser_decisions.json` | Adviser decisions applied after the release gate (Phase 1: mock entries) |
| `data/mock/` | Phase 1 only: invented MOCK notices, placeholder tender documents, recorded mock manual additions, firm-flag examples |
| `data/test_log_notes.json` | Learning / revision column of the test log (team-written) |
| `pipeline/` | Deterministic code, mock generators, trigger simulation, config — see `pipeline/README.md` |
| `prompts/` | Versioned prompts for the three AI tasks (Phase 2) |
| `outputs/{run_id}/` | Frozen runs (JSON + manifest with SHA-256). Never edited by hand |
| `config/website.json` | The one run the website displays |
| `i18n/` | `en.json`, `nb.json` (all UI strings) |
| `web/` | Next.js static site "Kvia" — see `web/README.md` |
| `tests/` | Fixture tests + end-to-end mock-run test (`python3 -m pytest -q tests`) |
| `test_log.md` | Prototype Test Log (Appendix A format) for the configured run |
| `docs/screenshots/` | Screenshots of each website view |

## Quick start

```bash
pip install -r pipeline/requirements.txt
python3 pipeline/run_mock.py            # regenerates outputs/mock-2026-11-05 and checks mode coverage
python3 -m pytest -q tests
cd web && npm ci && npm run build       # static export in web/out (base path /kvia-prototype)
```

Deployment: `.github/workflows/pages.yml` builds and publishes the site to GitHub Pages on every push to `main`
(enable Pages → "GitHub Actions" in the repository settings). The website never calls an AI model.
